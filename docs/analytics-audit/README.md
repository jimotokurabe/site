## 問題と変更

| 操作 | 既存 | 今回の変更 |
|---|---|---|
| 公式案内 | official_info_click、page_path/link_domain/link_path。自治体・行政ドメイン中心 | イベント名を維持。本文の出典リンクも判別し、交通事業者等を含める。リンク先はlink_domainのみ。一般外部リンク・LINE共有とは区別 |
| コピー | 複数機能に実装、成功計測なし | memo_copyを成功後のみ送信。feature_typeで機能区別。クリックだけ・拒否・手動コピー案内では送らない。execCommand代替もtrue時のみ。手動コピー完了は測れない |
| 試算 | 計算・表示はあるが成功計測なし | transport_estimate_view。実際に有効な結果DOMを表示した後、同一ページ寿命・地域につき1回。金額・回数・制度切替・地域を戻す再描画では重複しない |
| 地域対応 | 分類なし | transport_region_view。検証済み地域のsupported/unsupported/errorを分ける。地域未選択、未知ID、初期データ取得失敗は成功にも地域閲覧にも計上しない |
| ページ閲覧 | gtag configの自動page_view | 1回のconfigを維持、追加page_viewは発火しない。page_type、memo_available、静的地域ページのcity_idを付ける |
| 開発環境 | configのみホスト制限 | HTTPSの本番2ホスト・標準ポートだけ許可、noindexと端末除外設定ではGoogleタグ自体を読まない |
| URL情報 | ページURL等は既定値、独自リンクはパスまで送信 | canonicalのクエリ・ハッシュなしURLに統一。参照元はドメインだけ、ローカル参照元は空。リンク先パスを廃止 |

print_request、phone_click、share_line、related_support_clickは分析用に維持。印刷は要求の記録で、印刷成功ではない。関連支援のURLパス送信を廃止。独自イベントの配信はassets/analytics.jsに集約し、2,114公開ページで重複ロードを検査する。全国再生成では一部の旧アンカーが中間HTMLで失われるため、生成前に既存IDを取り出して最終生成へ引き継ぎ、古いページ内リンクを保持する。本文・制度データを変更するものではない。

コピーのfeature_typeはfamily_hint / city_guide / selected_supports / outing_plan / gomi_consultation / transport_costだけ。場面・回答・選択した制度のIDや本文は送信しない。

試算の「表示」は結果欄を表示状態にした意味であり、視線・熟読・利用資格・受給を測定していない。初期料金の例で自動表示されるため、強い意思表示とはみなさない。異なる地域の結果は別イベントでも、以下の率はユーザーの重複を除く。再読込は別ページ表示として記録できるが、ユーザー数をイベント数で代用しない。

## 送信範囲

送るもの：標準GAのCookie識別子、アクセス日時・端末等に加え、公開ページURL/タイトル、参照元ドメイン、ページ種別、メモ機能有無、公開地域ID（サイトで選んだ地域であり、居住地や位置情報の取得ではない）、コピー機能種別、試算対応状態、公式リンク先ドメイン。Google Signalsと広告パーソナライズはコードで無効。

送らないもの：自由入力・検索語・行き先・日時入力・回答/会話/支援の選択内容・メモ本文・金額・回数・電話番号・外部リンクのパス/クエリ/ハッシュ。ページURLのクエリ/ハッシュも除く。地域変更の実URLと共有URLは既存の公開ID引継ぎを保持する。解析用URLはUTM等も含めてクエリを除くため、URLクエリによるキャンペーン分析は今回の設計では保証しない。

**管理画面の自動計測をコードだけで無効にしたわけではない。** 次の設定変更と組み合わせて初めて自動イベント由来のURL等の送信経路を閉じる。現行管理設定のまま公開してプライバシー対応完了とはしない。

## 公開時に承認を求める具体案

1. GA4「管理 → データストリーム → じもとくらべ Web → 拡張計測機能の設定」で、離脱クリック・サイト内検索・フォーム操作・ファイルダウンロード・動画をOFF、ページビューの詳細設定「ブラウザの履歴イベントに基づくページの変更」をOFF。ページ読み込みとスクロールは維持。閲覧済みの現UIで項目を確認した。公式案内のPDFも独自official_info_clickに統一される。一般外部クリック・ファイル名・フォーム等の自動集計は以後なくなる。過去データは変わらない。
2. サイトの本差分（共通タグ、コピー成功フック、試算フック、プライバシー説明、生成HTML）を最新mainに差分統合し公開。同時進行変更との衝突は関連ファイルだけ解消し、古い全生成物をmainへ上書きしない。
3. イベントスコープのカスタムディメンションを5つだけ登録：page_type（ページ種類）、memo_available（メモ機能有無）、feature_type（コピー機能）、estimate_status（試算対応状態）、city_id（公開地域ID）。link_domainは標準の「リンクドメイン」を使用し、重複したカスタム定義は作らない。地域は分割分析に必要なときだけ使い、1,741地域の小さい件数を無理に横比較しない。
4. official_info_clickだけをキーイベントに登録し「セッションごとに1回」を推奨。行政・事業者の次の案内への移動という明示操作が理由。memo_copyはまず成功率の分析用、transport_estimate_viewは自動表示のため分析用。purchaseの既定設定を触らない。キーイベントのセッション集計と下記ユーザー率は別指標。
5. IPによる除外・データフィルタ変更は行わない。本番確認の端末は、公開前にDevTools等でlocalStorage.setItem('jk-analytics-disabled','1')を設定してから再読込すると計測を停止。解除はremoveItemで、既に読み込んだタブにも再読込が必要。共有IPで実利用者を落とさない。

設定OFF → コード公開 → 受信確認の順に行い、設定変更から公開までの時間を記録する。ロールバックではコードを戻しても自動検索/フォーム等は安易に再有効化しない。管理設定は現状を記録済みだが、適用直前に再読取りする。

## 最初の約2週間で見る3指標

集計単位は全て**総ユーザー数（期間内の重複を除いたGA識別ユーザー）**。イベント数・セッション数・アクティブユーザー数を分母に混ぜない。別端末、Cookie削除、計測拒否等で実人数とは一致しない。

GA4「探索 → 自由形式」で指標「総ユーザー数」を使う。下表それぞれについて分母のユーザーセグメントAと、同じ第1条件→第2条件を満たすユーザーシーケンスBを作る。条件内のevent_nameと各パラメータは**同一イベント**で一致させる。シーケンスは間に他のイベントがあってよい。期間内の順序を要求し、セッションをまたぐ同一ユーザーも含む。率=B/A、A=0なら「対象なし」。総ユーザー数を日別やページ別に足して期間合計にしない。

| 指標 | A：分母の閲覧ユーザー | B：Aの後に行動したユーザー |
|---|---|---|
| 自治体詳細→公式案内 | page_view AND page_typeがcity_detailまたはgomi_detail | official_info_click AND page_typeがcity_detailまたはgomi_detail |
| メモページ→コピー成功 | page_view AND memo_available=yes | memo_copy AND memo_available=yes |
| 移動費ページ→試算結果 | page_view AND page_type=transport_cost | transport_estimate_view AND page_type=transport_cost |

期間・本番ホスト・除外条件はA/Bで同一にする。個別ページの評価は両ステップに同じ「ページパス」の条件を入れる。交通詳細city_detailとごみ詳細gomi_detailの内訳も、両ステップを同じ種類に絞って出す。メモ機能別の率は対象ページ集合を先に固定し、分子のfeature_typeだけを変えて全サイト分母と比較しない。

移動費の補助表：transport_region_viewのestimate_statusをsupported / unsupported / errorで分け、総ユーザー数を表示。地域未選択・初期読込エラーではこのイベントがないので、全体閲覧ユーザーとの差を「未対応」と決めつけない。対応地域内の結果到達率は、A=transport_region_view AND supported → B=transport_estimate_viewの同じユーザーシーケンスで計算。個別地域を論じる場合は両段階を同じcity_idで絞る。同じ人が対応地域と未対応地域を見ることがあるため、地域状態別人数を足して全体人数にしない。

Googleのファネル探索を使う代替案では指標がアクティブユーザーとなるため、この総ユーザー方式と数値を混在させない。

記録欄：観測期間／定義版2026-10-16／A／B／B÷A／対応状態／テスト日／留意事項。最初は公開・設定・受信確認後の約14日間。母数と実数を併記し、少数なら期間を延ばす。イベントが少なくてもページ内で疑問が解決した可能性がある。これらは利用価値の目印であり申し込み・受給・満足度ではない。旧計測のないコピー・試算の改善効果は遡及算出しない。公式案内も事業者リンクを追加し定義が変わるため、旧件数との単純な改善比較はしない。定期実行・通知は作成しない。
