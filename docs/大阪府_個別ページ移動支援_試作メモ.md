# 大阪府の個別ページに移動支援を加える試作

## 目的と範囲

兵庫県で作った「返納後の移動に使えるもの」を、他府県の個別ページにも同じ仕組みで表示する。最初は大阪府の3市町だけを対象にする。公式出典と返納特典との関係を確認できた市町に限って `data/<府県>-taxi.json` の `guide_mobility` を `true` にする。既存の一覧データを再利用し、個別ページ用に制度の事実を二重管理しない。

| 市町 | 関係 | 個別ページの表示 |
|---|---|---|
| 枚方市 | 別制度。ただし返納特典のひらかたポイントをクーポンに交換できる | 対象・交換方法と連絡先を一つの節に集約。従来の重複する説明を削除 |
| 豊能町 | 返納支援そのものに京都タクシーの利用券が含まれる | 同じ制度と分かる案内と、ページ内の申込手順へのリンク |
| 池田市 | 確認した高齢福祉サービス案内ページに年齢だけを条件とするタクシー助成の記載なし | 確認範囲を明示し、重度障がい者向け制度と混同しない案内 |

3市町の移動支援の公式ページを2026年10月3日に再確認した。返納手順など、ページ全体の確認日は従来の2026年9月27日のままにする。

## 次の市町の作り方

1. 既存の `data/<府県>-taxi.json` と `data/<府県>-menkyo-henno.json` を照合する。すでに個別ページに同じ移動制度の説明がある場合は重複を整理する。
2. 市町の公式ページで対象、金額、申込方法、返納特典との関係を原文で確かめる。見つからない場合は「確認したページ」の範囲で書き、制度が存在しないと断定しない。
3. `guide_mobility: true` と市町別の `checked` を付ける。同じ制度は `guide_relation: "same"`、別制度の関係を伝えるときは `guide_relation_note` を使う。追加の手順が必要なときだけ `guide_details` を使う。
4. `python3 tools/build.py --out /tmp/<作業フォルダ> --draft` で下書きを作る。`DIR=<府県>-menkyo-henno` を指定して `tools/check_guide.js` を動かし、リンクも `tools/check_links.py` で確かめる。
5. 1府県につき数市町ずつレビューし、オーナーの「公開して」の後に生成済みHTMLとデータを同じコミットで公開する。

## クレジットを抑える方法

- 定型のHTMLはビルダーが生成する。市町ごとにAIへ全文作成を依頼しない。
- 公式ページの確認は条件や関係が曖昧な箇所に集中し、端末幅・リンク・印刷はローカルの検査を使う。
- 初回3件で表示と文章を確定してから同じ型を使ってまとめて進める。`notfound` は探索範囲を記録し、推測で内容を増やさない。
- Codexの使用率表示は週単位の整数値で、作業1件あたりのクレジットを精密には測れない。試作前後の表示を参考値として記録する。

## 試作の確認

- 3ページともスマートフォン幅390pxと大きい文字で横はみ出しなし。
- 一覧からの入口、URLコピー、印刷、LINE共有が動作。
- A4印刷はいずれも2ページ。
- 3ページの出典リンクはすべてHTTP 200。
- 大阪府の他の個別ページは `guide_mobility` がないため表示が変わらない。

公開はオーナーのプレビュー確認後。`GUIDES.md` の手順に従う。
